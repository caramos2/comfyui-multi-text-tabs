1. 项目目标与产品定义
本项目开发一个新的 ComfyUI 文本节点。它不是把多个 STRING 输出口堆在同一个节点上，而是把多份可独立编辑、可长期保存的文本放入同一个标签容器。用户通过顶部标签栏切换文本，点击“+”创建新标签，编辑区始终只显示当前选中的文本。
| 核心产品定义
一个节点 = 多个文本仓库 + 一个当前文本编辑器 + 一个 STRING 输出。执行时只输出当前活动标签的文本；未选中的标签仅作为节点内部素材保存。
|

1.1 目标体验
节点创建后默认有一个标签：Text 1。
点击顶部标签即可切换；切换前自动保存当前编辑内容，切换后载入目标标签内容。
点击“+”立即创建新标签并切换过去，默认命名 Text N，内容为空。
支持关闭、重命名、复制标签；至少保留一个标签。
工作流保存、关闭 ComfyUI、重新打开、复制节点、复制工作流后，标签名称、文本、当前选中标签均应恢复。
输出端只有一个标准 STRING，始终输出当前活动标签内容，兼容现有文本管线。
1.2 非目标（首个版本不做）
不做多个 STRING 输出端口，也不为每个标签动态创建 socket。
不做节点之间的共享文本库、跨节点引用或远程同步。
不把它做成完整 Flowith 无限画布；本项目仅聚焦“单节点多文本收纳”。
不在首版加入富文本、Markdown 预览、变量面板或复杂模板管理。编辑内容仍是普通纯文本。

2.2 建议的快捷交互（第二阶段）
Ctrl + Tab：切换到下一个标签；Ctrl + Shift + Tab：切换到上一个标签。
Ctrl + N：创建新标签；快捷键仅在节点获得焦点时响应，避免抢占浏览器快捷键。

3. 技术架构：推荐采用“节点属性保存标签 + 标准 Widget 输出当前文本”
| 首选架构（推荐）
全部标签数据与活动标签 ID 保存到前端节点的 properties 对象；当前活动文本同步到一个标准 STRING 多行 Widget。Python 后端只接收 active_content 并输出 STRING。首版不需要隐藏 JSON 输入。
|

3.1 为什么不把 tabs_data 作为隐藏后端输入
你提供的初稿用 tabs_data JSON 字符串传输完整标签集合，再用 active_content 作为后端输出。这种方案可以实现，但会让“仅供界面保存”的数据进入执行输入模型，增加隐藏 Widget、提示词序列化和缓存管理负担。ComfyUI 当前前端明确区分工作流持久化与 API Prompt 序列化：widget.serialize 控制工作流保存，widget.options.serialize 控制是否进入执行请求。两者不能混为一谈。
更进一步，ComfyUI 的节点序列化结构本身包含 properties 字段，可用于保存节点自己的界面状态。标签内容不需要进入后端执行输入；只需把活动文本交给 Python 节点。这样不活动的文本被编辑时，不会因为 tabs_data 改变而影响执行输入。

4. 后端节点设计（Python）
4.1 后端职责
注册一个标准 ComfyUI 自定义节点。
接收 active_content 这一项 STRING 输入。
返回完全一致的字符串，不擅自拼接标签、修剪空白或执行提示词替换。
不负责读取前端 properties；也不接收 tabs JSON。
4.2 建议的节点接口
class MultiTextTabsNode:
@classmethod
def INPUT_TYPES(cls):
return {
"required": {
"active_content": (
"STRING",
{
"default": "",
"multiline": True,
"dynamicPrompts": False
}
)
}
}

RETURN_TYPES = ("STRING",)
RETURN_NAMES = ("text",)
FUNCTION = "get_text"
CATEGORY = "utils/text"

def get_text(self, active_content):
return (active_content,)
|

说明：这是后端接口示意，实施时应按目标 ComfyUI 版本的节点注册规范调整，不要把它当成已经测试过的完整插件。dynamicPrompts=False 的目的是让文本内容保持原样；如果你希望保留 ComfyUI 动态提示词语法，可将其做成可配置选项。

5.3 Widget 同步规则（最重要）
节点创建：若没有 multi_text_tabs，则创建 version=1、一个 Text 1 空标签；把该标签内容同步到 active_content。
用户编辑：将编辑器当前值写入 active_content Widget，并同步写入活动标签的 content。不得只更新其中一处。
切换标签：先读取 Widget 当前值并写入旧活动标签，再变更 active_id，最后把新活动标签的 content 写入 Widget。
新增标签：先 flush 当前内容；创建唯一 ID；追加空内容标签；设为 active_id；Widget 清空。
工作流保存：在 onSerialize 或对应保存生命周期中再次 flush 当前 Widget 到 properties，防止最后一刻输入尚未同步。
工作流载入：恢复 properties；检查 active_id 是否存在；把活动标签内容与 Widget 值对齐；如果没有旧属性，使用现有 active_content 初始化 Text 1。
| 一致性原则
任何时刻都必须满足：active_content Widget 的值 = tabs[active_id].content。所有切换、保存、执行前都要确保此不变量成立。
|

5.4 标签栏渲染技术路线
建议把 UI 渲染封装成独立 TabBar Adapter，不要让业务状态逻辑依赖某一种绘制 API。先验证当前 ComfyUI 前端版本的节点渲染模式，再选择具体实现：
优先路线：使用当前前端支持的自定义 Widget / DOM Widget / Vue 渲染扩展能力，实现标签栏与原生 textarea 编辑器的组合。它更适合现代界面与文本输入交互。
兼容路线：若当前部署仍使用经典 LiteGraph Canvas，可用节点级绘制回调绘制标签，并对标签区域做局部 hit-test；不得直接全局重写 onMouseDown 等原型。
两条路线共用 State Manager、Widget Bridge 和 Python 后端。未来前端渲染变化时只替换 Tab UI Adapter。
不建议把“直接改 LGraphNode 原型 + 手工定位 DOM textarea”作为唯一实现。ComfyUI 前端持续演进，官方扩展指南也强调使用扩展钩子、减少对核心对象的直接修改；现代 Vue Widget 渲染与旧版 DOM 访问习惯存在兼容风险。
5.5 鼠标事件与命中区域
仅在标签栏区域拦截点击；编辑器区域、节点标题栏、输出插槽和缩放手柄继续走 ComfyUI 原生行为。
为每个可交互元素维护清晰 hitbox：标签本体、关闭 ×、新增 +、左右滚动区域。
点击关闭按钮不能误触发标签切换；点击标签不能意外拖动节点。
双击重命名建议使用 ComfyUI 兼容的对话框或轻量输入层，不直接依赖浏览器 prompt。
6. 工作流持久化、复制与兼容性
6.1 持久化策略

6.3 数据恢复与迁移规则
properties 缺失：以 active_content 当前值创建 Text 1。
tabs 为空或不是数组：重建一个空标签。
active_id 不存在：选择第一项作为活动标签。
重复 ID：为冲突标签重新分配 ID，不能把两份内容合并。
content 不是字符串：安全转换为空字符串或 JSON 字符串，并记录控制台警告。
未知 version：保留可读取字段，执行迁移或回退到安全默认状态，不让节点加载失败。
7. 执行缓存、性能与边界设计
7.1 执行缓存原则
后端仅接收 active_content，因此只编辑非活动标签时，不应改变节点的执行输入；切换到另一标签后，active_content 改变，才构成新的执行输入。这里是把标签状态放入 properties 而非额外后端输入的核心价值。
7.2 性能要求
只渲染可视标签与当前编辑器，不为每个标签创建独立 textarea / Widget。
标签数量增长时采用横向滚动、活动标签自动定位；不因标签数量而显著改变节点高度。
建议以 1、10、50、100 个标签进行压力测试；100 个作为首轮软性能警戒点，不作为产品层面的强制上限。
避免每次输入都重绘整个节点；状态更新应局限于当前标签和必要的 UI。
7.3 文本行为
默认保留换行、空格、标点与原始文本，不自动 trim。
支持中英文、Emoji、长提示词和多段落文本。
内容大小由 ComfyUI 工作流 JSON 承载；超大工作流可显示体积警告，但首版不偷偷截断文本。

☐  节点能正常加载，重启后不报 Python 导入错误或前端 JS 错误。
☐  初始创建时只有 Text 1，点击 + 可连续创建多个标签。
☐  每个标签的内容完全独立；切换标签不会覆盖其他标签文本。
☐  切换前最后输入的字符、换行和空格均能保存。
☐  关闭活动标签后能切换到合理的相邻标签；永远至少保留一个标签。
☐  重命名和复制标签不会改变其他标签内容。
☐  保存工作流、刷新页面、重新打开工作流后，所有标签与活动选择恢复。
☐  复制粘贴节点后，副本保留完整标签内容且与原节点互不影响。
☐  只修改非活动标签时，后端执行输入仍保持当前活动文本。
☐  切换到另一标签后，下游 STRING 节点收到新活动文本。
☐  编辑区支持长文本、多行、中文、Emoji；不截断、不丢字符。
☐  标签很多时可横向滚动，节点尺寸和画布交互仍正常。
☐  标签栏的点击不会意外拖动节点、触发连线或误操作关闭节点。
☐  在目标前端模式下，标签 UI 不出现空白、错位、不可点击或 DOM 报错。
10. 风险清单与规避措施
风险
| 可能表现
| 规避策略
|
前端渲染版本差异
| Canvas 回调在新渲染模式下行为变化，或 DOM Widget 不显示。
| P0 先探测部署版本；Tab UI 与状态逻辑分层；至少测试目标 UI 模式。
|
Widget 与 properties 不一致
| 切换标签或保存时丢失最后输入。
| 建立 active_content = active_tab.content 不变量；切换前 flush；保存前再次同步。
|
回调覆盖原生行为
| 节点不能拖动、点击标签失灵、输出口点击异常。
| 只包装目标节点方法；保留并调用原回调；精确限制 hitbox。
|
复制粘贴数据丢失
| 副本只有当前文本，没有其他标签。
| 专门测试 clone→serialize→configure 流程；不要仅测试保存工作流。
|
标签数据损坏
| 工作流加载异常或活动标签为空。
| 使用 versioned schema、强校验、自动恢复与迁移。
|
不安全的 DOM 插入
| 标签标题或正文被当作 HTML 解析。
| 用 textContent / 安全文本节点；固定 properties 键名；禁止将用户文本拼入 innerHTML。
|

11.1 不得违反的架构约束
不得把全部文本拼接后输出；默认输出严格等于当前活动标签正文。
不得把标签正文依赖 localStorage/sessionStorage；工作流文件必须是权威持久化来源。
不得在 Python 后端重复存储前端标签数据；前后端职责必须分开。
不得全局覆盖 LGraphNode.prototype 或其他核心原型来实现单个节点 UI。
不得在切换标签时重建整个节点；只更新活动 ID 与文本 Widget。
不得静默截断用户长文本；对异常状态应修复或提示。
