# 变更说明 · Multi-Text Tabs

## v1.3（2026-11-16 · 新增「主输出」端点）

主人新诉求：**「添加一个 main output 输出端点，它的作用是输出当前文本……设置这个的意义在于
有些时候只需要连接主输出，然后切换不同的文本进行任务，而不用重新切换至对应 text 序号的接线」**。

v1.3 实现了这个端点：节点右侧现在除了每条待命文本各一个端点，**末尾多一个「主输出」**，
它**永远输出当前选中的那条待命文本**。下游只接这一根线，切换标签就换内容，不用改接线。

### 端点布局

```
节点右侧：  ● 待命文本 1     ● 待命文本 2     ● 待命文本 3     ● 主输出
序号：        0               1               2               3（= 待命文本条数）
```

- 文本端点数量 = 待命文本数量，名称随文本名同步（沿用 v1.2）。
- 主输出固定在**末尾**，序号 = 当前待命文本条数。
- ★ 放在末尾是刻意的：**ComfyUI 后端只按端点「序号」解析连线**（@execution.py:953@
  `received_type = RETURN_TYPES[val[1]]`），名字不参与。放在末尾意味着
  **已有工作流里文本端点的序号一个都不会错位**，老工作流直接可用。

### 载荷格式变了（向后兼容）

widget 值从 JSON 数组改成 JSON 对象，多带一个「当前是哪一条」：

```json
{"texts": ["第一条", "第二条"], "active": 1}
```

后端同时接受旧写法：纯数组（@["a", "b"]@）→ 视为没有活动项，主输出取第一条；
纯文本 → 视为单条文本。所以 v1.2 存的工作流、手写的 API prompt 都能继续跑。

### 后端槽位

后端输出从 16 槽变成 17 槽：

- 槽 0..N-1 = N 条待命文本（按标签顺序）
- 槽 N..16 = **当前待命文本**（主输出落在槽 N；后面的槽填一样的值，
  这样前端主输出端点无论落在哪个槽位，拿到的都是当前文本）

### 真机踩到的三个坑（已修 + 已加回归测试）

1. **@graph.links@ 是 Map，而且没有 @getLinkById@**：按数组下标 @links[id]@ 取连线**取不到**，
   连线重编号会静默失效。
2. **连线登记在 @link.origin_slot@ 上，槽位的 @links@ 是按序号算出来的「派生视图」**：
   插入一个端点后，视图会立刻错位 —— 表现为「主输出送出的是另一条文本」，
   再关掉一条文本时那条连线直接被删掉。必须同步改 @origin_slot@。
3. **LiteGraph 的 @addOutput@ 只追加、@removeOutput@ 自己会把后面连线的序号减 1**：
   实测确认，所以插入要自己 splice + 改 @origin_slot@，删除交给 LiteGraph。

## v1.2（2026-11-16 · 一条待命文本一个输出端点）

主人提出新诉求：**「点击加号可以出现更多空白分页可输入文本」「Text 1 实为待命文本 1，
待命文本 2」「数量也要与右侧输出端点统一，方便我传出的值究竟是哪一串文本」**。

v1.2 按此重做了节点的输出模型：**每条待命文本在节点右侧拥有自己的 STRING 输出端点，
端点数量与待命文本数量一致，端点名与文本名同步。**

### 命名口径

- 「标签 / Text N」统一改称 **「待命文本 / 待命文本 N」**，界面文案全中文。
- 自动命名的待命文本按所在位置重编号（`renumberAutoTitles`）：
  删掉第 2 条后，剩下的自动名重新读作 `待命文本 1`、`待命文本 2`。
- 用户手工改过名的待命文本保留自定义名，其输出端点也跟着用这个名字。

### 输出端点

| 项 | v1.1 | v1.2 |
|---|---|---|
| 后端输出 | 1 个 `text` | 固定 16 个 STRING 槽 |
| 端点名 | `text` | `待命文本 1 … 待命文本 16` |
| 前端可见端点 | 1 个 | **与待命文本数量一致**（`syncOutputs()` 动态增删/改名） |
| 端点命名 | 固定 | 随文本名同步，改名即时生效 |

后端之所以固定 16 个槽：ComfyUI 的 `execution.py` 用 `RETURN_TYPES[slot]` 校验
连线，输出数量一旦变化旧连线就会错位。所以**后端槽数不可变，动态的部分放在前端** ——
前端按待命文本条数增删/改名输出端点并同步调整节点高度。

### 架构反转（重要，且有代价）

计划书 `3.1 的口径是「标签数据不进后端，只有当前标签正文进后端」。
v1.2 因为「每条文本一个输出端点」，**所有待命文本都必须进后端** —— 这是本次的架构反转：

- widget 值从「当前文本」改为 **JSON 数组**（一条待命文本一个元素，按顺序）；
- `widget.options.serialize = true` → JSON 数组进执行请求；
- `widget.serialize = false` → JSON 数组**不进工作流文件**，正文唯一权威副本仍是
  `node.properties.multi_text_tabs`。

**代价（必须知道）**：因为全部文本都进执行输入，**编辑任意一条待命文本都会改变节点的
执行输入，使 ComfyUI 对该节点的执行缓存失效**。v1.1 只有活动标签进后端，改不动
活动的标签不会碰缓存。这是「一条一个端点」的必然成本，已在此明写。

### 其它

- 后端解析：JSON 数组原样拆出；坏 JSON / 纯文本降级为「单条文本」，手写 API prompt 仍可用。
- 超出 16 条时点 ＋ 会提示「最多 16 条待命文本」，不静默截断。
- `dynamicPrompts=False`：正文里的 `{weight:1.5}` 之类不做插值，文本逐字保留。

## v1.1（2026-11-16 · 真机验收修复）

真机验收（ComfyUI v0.45.0 + 前端 1.58.5，浏览器实测）发现并修复三个真实缺陷。
三个都在前端，后端未改动，**工作流文件格式也没有变化**（v1.0 存的工作流可直接打开）。

### 修复 1（根因）：标签改动会写进「孤儿对象」

**现象**：点 ＋ 加不出标签（标签数恒为 1）、编辑区被清空、重命名不生效。

**根因**：前端把 `node.properties` 放在 Vue reactive 对象里
（`LGraphNode.get properties(){ return this._state.properties }`）。
写进去的是原始对象，读回来的是它的 reactive 代理：

    node.properties[KEY] = X      // 写入原始对象
    node.properties[KEY] === X    // false —— 读回来的是 reactive(X)，不是 X

v1.0 用 `===` 判断「状态有没有被换掉」，这个判断**永远为假**，
于是每次读状态都重新归一化并**整体替换** `properties[KEY]`。
一次操作里先后拿到两个不同的状态对象，前一个成了孤儿：
`addNewTab()` 里 `addTab()` 改的是那个孤儿，节点本身纹丝不动。

**修复**：不再用对象身份判断，改用藏在状态里的**标记（marker）**。
marker 是不可枚举属性，**不写进工作流文件**；
`state()` 永远返回同一个对象；外部替换（载入工作流 / 复制 / 撤销）
则因 marker 不匹配被自动识别并接管。

### 修复 2：双击重命名与右键菜单点不到

`attachEvents()` 在**捕获阶段**对 `dblclick` / `contextmenu` 调用了 `stopPropagation`，
事件在到达标签栏之前就被拦下，标签栏上的处理器根本收不到。

现改为：`pointerdown` / `mousedown` / `wheel` 仍在捕获阶段拦（防止拖动节点、缩放画布），
`dblclick` / `contextmenu` 改到**冒泡阶段**拦 —— 自己的处理器先跑完，再挡住画布。

### 修复 3：前端收不到「节点变了」的通知

`widget.callback` 在本前端默认为 `undefined`，原来的通知调用是空操作。现在：

- 文本与标签改动通过 `widget.value = ...` 走前端自己的 setter（`options.setValue` + callback）；
- 结构性改动（增 / 删 / 改名 / 复制 / 切换）用前端同款模式包裹：
  `graph.beforeChange()` → `canvas.emitBeforeChange()` → 改动 →
  `graph.afterChange()` → `canvas.emitAfterChange()` → `node.setDirtyCanvas(true, true)`。

## v1.0（2026-11-16）

## 新增

- ComfyUI 自定义节点 **Multi-Text Tabs**（`utils / text` 分类）：
  一个节点内收纳多份文本，顶部标签栏切换，一个编辑区，一个标准 STRING 输出。
- 后端 `nodes.py` / `__init__.py`：单 STRING 输入 `active_content`，单 STRING 输出 `text`，
  文本原样返回，不拼接、不 trim、不做提示词插值。
- 前端 `web/multi_text_tabs.js`：扩展注册（`beforeRegisterNodeDef` / `getCustomWidgets` /
  `nodeCreated` / `loadedGraphNode`），单 DOM widget 承载「标签栏 + 编辑区」。
- 前端 `web/multi_text_tabs_state.js`：**纯逻辑**状态机（无 DOM 依赖，可独立单测），
  负责标签集合的增删改切复制、ID 唯一性、数据校验与损坏修复、版本迁移。
- 前端 `web/multi_text_tabs.css`：节点内样式，全部以 `.mtt-` 前缀作用域隔离。
- 测试：`tests/test_nodes.py`（后端 8 项）、`tests/frontend/state.test.mjs`（状态机 26 项）、
  `tests/frontend/check_extension.mjs`（假 DOM 端到端 18 项）。
- 验收工作流：`Multi-Text Tabs 验收工作流.json`（已放入 ComfyUI 工作流库），
  含 Multi-Text Tabs → Preview as Text / Save Text 两条下游验证链路。
- `README.md`：安装、功能、兼容性、使用方法、故障排查、测试说明。

## 行为约定

- 默认只有一个 `Text 1`；点 ＋ 追加 `Text N`（编号不重复已用过的）。
- 切换标签前先把编辑区内容写回当前标签，**因此不会丢最后一个字**。
- 关闭标签：永远至少保留一个；关闭非空标签会给一次**撤销**机会。
- 重命名：双击标签就地编辑；复制：右键菜单，副本名为「原名 Copy」并立即激活。
- 标签过多时标签栏横向滚动，活动标签自动滚入可视区。
- 标签正文原样保留：换行、空格、中文、Emoji、`{weight:1.5}` 之类都不改写。

## 数据存放

| 数据 | 位置 | 是否进后端 |
|---|---|---|
| 全部标签标题与正文 | `node.properties.multi_text_tabs` | 否 |
| 当前活动标签 ID | `node.properties.multi_text_tabs.active_id` | 否 |
| 当前活动标签正文 | widget `active_content` | 是 |

工作流文件是唯一持久化来源，不使用 localStorage / sessionStorage。

## 已知限制（v1.0 当时状态）

- 画面对不对（标签栏位置、滚动、重叠）**尚未在真实 ComfyUI 里跑过** ——
  v1.1 已完成真机验证，此条作废。
- 快捷键 `Ctrl+Tab` 在部分浏览器里会被浏览器自身占用，此时改用 `Ctrl+N` 与点击标签。
- 单个标签正文过大时（数万字），前端每次按键会重写一次 properties 对象；
  不做分片，但未静默截断任何文本。
