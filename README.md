# Multi-Text Tabs（多文本标签节点）

一个 ComfyUI 自定义节点：把多份文本收纳进**同一个节点**，每条文本在右侧各有一个 **STRING 输出端点**，末尾还有一个 **「主输出」**端点——它永远输出当前选中的那条文本。

```
┌────────────────────────────────────────────────────────────┐
│  Multi-Text Tabs   [待命文本 1] [待命文本 2] [待命文本 3]  [+]│
├────────────────────────────────────────────────────────────┤
│  当前待命文本（主输出）：待命文本 2                           │
│  A cinematic close-up, soft rim light, detailed fabric...   │
│  ...                                                        │
└────────────────────────────────────────────────────────────┘
     ● 待命文本 1   ● 待命文本 2   ● 待命文本 3   ● 主输出
```

> 界面文案、代码注释与文档均为中文；英文版见 [README.en.md](README.en.md)。

## 功能

- **一条文本一个端点。** 输出端点数量永远等于待命文本数量，每个端点以它承载的文本命名（`待命文本 1`、`待命文本 2`，或你自己改的名字）。不拼接、不隐藏在一个笼统的"当前输出"后面。
- **多一个「主输出」端点。** 它永远携带当前选中的待命文本。下游只接这一根线，切换标签就切换送出的内容——不用改接线、不用记槽位序号。
- 点 **＋** 新建一条空白待命文本，立刻就能输入。
- 标签栏在编辑区上方，编辑区随节点一起变高。
- 支持关闭（×）、重命名（双击）、复制（右键）。
- 关闭非空文本时给一次**撤销**机会，而不是弹一个阻塞式对话框。
- 标签栏横向滚动，文本再多也挤在一个节点里。
- 切换文本**不会丢掉最后一次输入**——编辑区是唯一真相来源，切换前先落盘。
- 中文、英文、Emoji、超长提示词都能用；不 trim、不插值，`{weight:1.5}` 这类花括号原样保留。

## 安装

把整个仓库克隆或下载到 ComfyUI 的 `custom_nodes` 目录下，然后重启 ComfyUI：

```
ComfyUI/
└── custom_nodes/
    └── ComfyUI_MultiTextTabs/      ← 仓库根目录就是插件包
        ├── __init__.py
        ├── nodes.py
        ├── web/
        │   ├── multi_text_tabs.js
        │   ├── multi_text_tabs_state.js
        │   └── multi_text_tabs.css
        └── tests/
```

也可以直接 `git clone`：

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/caramos2/comfyui-multi-text-tabs.git
```

重启后，节点出现在分类 **utils / text** 下，显示名为 **Multi-Text Tabs**。

## 快速开始

1. 在画布上添加 **Multi-Text Tabs** 节点。
2. 点 **＋** 建几条待命文本，分别填入不同内容。
3. 把 **主输出** 接到下游节点（例如 **Preview as Text** 或 **Save Text**）。
4. 点不同的标签，再点「运行」——送出的就是当前选中的那条文本。

想固定某一条文本，就直接接它的专属端点（`待命文本 1`、`待命文本 2`……），两条线各走各的。

## 使用

| 操作 | 结果 |
|---|---|
| 点击待命文本 | 先提交当前编辑区内容，再切换过去；主输出随之携带该文本 |
| 点击 ＋ | 新建一条名为 `待命文本 N` 的空文本并切换过去 |
| 点击 × | 关闭该文本。最后剩下一条时不会被关掉 |
| 双击文本 | 就地重命名，输出端点同步改名 |
| 右键文本 | 菜单：重命名 / 复制 / 关闭 |
| `Ctrl` + `Tab` | 下一条（仅当节点有焦点时） |
| `Ctrl` + `Shift` + `Tab` | 上一条 |
| `Ctrl` + `N` | 新建一条文本 |

每个端点都是标准 STRING 输出，可以接到任何接受 STRING 的节点。

### 命名

- 没改过名的文本叫 `待命文本 N`，N 是它的位置。删掉一条后，其余自动名重新编号，列表永远读作 `待命文本 1`、`待命文本 2`、`待命文本 3`。
- 改过名的文本保留自己的名字，输出端点也用同一个名字。

### 数据存放

| 数据 | 位置 | 是否进后端 |
|---|---|---|
| 全部文本标题与正文 | `node.properties.multi_text_tabs` | 是（作为一段 JSON 载荷） |
| 当前活动文本下标 | 同上 | 是（载荷的一部分） |
| widget 值 | widget `texts`（JSON 载荷） | 是 |

载荷长这样：

```json
{"texts": ["第一条", "第二条"], "active": 1}
```

刻意用了两个互不相同的序列化开关：

- `widget.serialize = false` → JSON **不进**工作流文件，正文唯一权威副本在 `node.properties` 里；
- `widget.options.serialize = true` → JSON **进**执行请求，全部文本都能被后端拿到。

**一个需要知道的代价：** 因为每条文本都有自己的输出，全部文本都必须进后端。于是**改动任意一条文本都会改变节点的执行输入，使 ComfyUI 对该节点的执行缓存失效**。v1.1 只发送当前活动文本，改动其它文本碰不到缓存。这是"一条文本一个端点"的必然成本。

工作流文件是唯一的持久化来源。**不使用** `localStorage` / `sessionStorage`，所以工作流可以随意分享、版本化、导入到任何地方。

## 项目结构

```
.
├── __init__.py              节点类映射、显示名映射、前端目录声明
├── nodes.py                 后端：解析载荷并把文本原样送回
├── web/
│   ├── multi_text_tabs.js        前端扩展（DOM widget + 标签栏 + 端点管理）
│   ├── multi_text_tabs_state.js  纯逻辑状态机（无 DOM 依赖，可独立单测）
│   └── multi_text_tabs.css       节点内样式，全部以 .mtt- 前缀作用域隔离
├── tests/
│   ├── test_nodes.py             后端契约测试（15 项）
│   └── frontend/
│       ├── state.test.mjs        状态机单测（34 项）
│       └── check_extension.mjs   假 DOM 端到端（31 项）
└── docs/                        技术文档（验证报告、变更说明、技术蓝图）
```

**架构分三层**（详见 [docs/P0-技术验证报告.md](docs/P0-技术验证报告.md)）：

- **状态管理器**（`multi_text_tabs_state.js`）：纯函数，不碰 DOM，也不依赖 ComfyUI，所以能直接用 Node 做单测。
- **widget 桥接**（`multi_text_tabs.js`）：负责 widget 值与标签状态保持同步。
- **标签 UI**（`multi_text_tabs.js`）：在 DOM widget 内部用原生 DOM 实现。

### 为什么「主输出」固定排在末尾

ComfyUI 后端解析连线时**只看端点序号**，不看端点名（`execution.py` 里是 `received_type = RETURN_TYPES[val[1]]`）。主输出排在末尾，意味着**已有工作流里文本端点的序号一个都不会错位**，老工作流直接可用。

## 测试

三套测试都不需要浏览器，也不需要跑起来的 ComfyUI：

```
python tests/test_nodes.py                     # 15  后端契约
node tests/frontend/state.test.mjs             # 34  文本状态机
node tests/frontend/check_extension.mjs        # 31  假 DOM 端到端
```

`check_extension.mjs` 把实际发布的 `web/multi_text_tabs.js` 载入 `node:vm` 上下文，配一个有边界的假 DOM——**测的就是发布的那个文件**。它还复刻了真实前端的 reactive `node.properties`（v1.0 的状态身份缺陷就出在那里），以及真实前端的输出端点 API，包括"按槽位序号登记连线"这套机制，因此"一条文本一个端点 + 主输出"的行为与连线簿记都被覆盖到了。

## FAQ

**Q：节点只有一个光秃秃的输入框，没有标签栏？**
前端扩展没加载。打开浏览器控制台看 `multi_text_tabs.js` 的报错；强制刷新（`Ctrl` + `Shift` + `R`）会重新加载扩展。

**Q：完全看不到输出端点？**
节点定义没重新加载。装好插件后重启 ComfyUI，再强制刷新浏览器。

**Q：主输出送出的文本不对？**
浏览器还在跑旧版本扩展。强制刷新（`Ctrl` + `Shift` + `R`），并看一眼节点状态行显示的是哪一条。

**Q：打开旧工作流后端点不见了？**
那个工作流是 v1.0 / v1.1 存的，用的是单个 `text` 输出。文本本身还在，升级后重新添加端点即可。

**Q：明明有内容，编辑区却是空的？**
存下来的状态损坏了。节点会自我修复并把原因打印在浏览器控制台。

**Q：`Ctrl` + `Tab` 没反应？**
部分浏览器会把这个快捷键占走。改用 `Ctrl` + `N` 或直接点标签。
